# Simulations for non-binding futility in MAMS

Operating characteristics (FWER, power, ESS) of designs from `MAMS::mams()` with
`binding = TRUE` / `FALSE`, evaluated with `MAMSS`.

## Requirements

- `MAMS` with the `binding` argument (fork `ichbindas/MAMS`, branch `non-binding-futility`)

  ```r
  remotes::install_github("ichbindas/MAMS@non-binding-futility")
  ```

- `MAMSS` (`dlc48/MAMSS`)
- `dotfunctions` (`dlc48/dotfunctions`, installed by `0-par.r` if missing)
- `mvtnorm` (binary designs only)

## Folders

| Folder | Design boundary | Futility in simulation |
|---|---|---|
| `binding` | binding | applied |
| `non-binding` | non-binding | ignored (worst-case FWER) |
| `non-binding-enforced` | non-binding | applied (realistic power / ESS) |
| `binary-*` | same three variants, binary endpoint | |

Binary designs take their sample size from `binary-design-helper.R` (accounts for the H1
variance of the pooled two-proportion test); boundaries still come from `mams()`.

## Running

From inside a design folder:

```
Rscript 0-par.r
Rscript 1-run.r 1 in out
Rscript 2-pdf.r 1 in out pdf
```

`0-par.r` writes the config grid to `in/par` and resets `out/`, `1-run.r` simulates every config
(R = 25,000 trials each; expect hours), `2-pdf.r` writes `pdf/initial-<method>.pdf`.

## Results

- `non-binding-results.md` / `.pdf` — normal endpoint, all three designs
- `binary-results.md` / `.pdf` — binary endpoint; regenerated by `Rscript make-binary-results.R`
  from `binary-extracted.rds` (metrics extracted from the `out/` folders of the binary runs)
- `*/pdf/` — per-config output of the runs the reports are based on

Raw simulation output is written to `out/` by `1-run.r` (~500 MB in total) and is not distributed with the reports.
